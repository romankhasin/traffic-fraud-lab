# Traffic Fraud Lab

Инструмент для локального анализа дневных выгрузок Яндекс Метрики на возможные признаки фрода и низкокачественного трафика.

## Что умеет версия 0.5

- принимает две выгрузки CSV/XLSX: `Дата + источник + IP` и `Дата + источник + технические параметры`;
- требует дневную группировку в обоих файлах;
- автоматически распознаёт русские и английские названия столбцов;
- читает ClientID как текст, не преобразуя длинный идентификатор в JavaScript Number;
- объединяет данные по `UTM Source × дата`;
- сравнивает каждый день только с остальными днями того же источника;
- использует устойчивую базу на медиане и MAD, исключая проверяемый день из сравнения;
- анализирует дневной объём, отказы, время, долю новых пользователей, конверсии, IP/подсети, ClientID и технические профили;
- рассчитывает дневной risk score от 0 до 100 и уверенность оценки;
- показывает аномальные даты внутри карточки каждого источника;
- оценивает количество визитов, совершённых в аномальные дни, и суммирует их по месяцам;
- экспортирует дневные результаты в CSV.

## Приватность

Файлы обрабатываются JavaScript-кодом непосредственно в браузере. Исходные IP-адреса, ClientID и строки выгрузок не отправляются в репозиторий или на внешний сервер. Для чтения CSV/XLSX используется клиентская библиотека SheetJS с CDN.

## Обязательные поля

### IP-выгрузка

- Дата визита / Дата / Day;
- UTM Source / Источник;
- IP-адрес;
- Визиты.

Желательные поля:

- Посетители;
- Отказы;
- Время на сайте;
- Доля новых посетителей;
- конверсии.

ClientID в IP-выгрузке не требуется и не участвует в расчёте, даже если такая колонка случайно присутствует.

### Техническая выгрузка

- Дата визита / Дата / Day;
- UTM Source / Источник;
- Визиты.

Желательные поля:

- Версия браузера;
- Операционная система;
- Модель или тип устройства;
- Разрешение;
- Отказы;
- Время на сайте;
- Доля новых посетителей;
- конверсии;
- ClientID / Client ID / ym:s:clientID.

ClientID берётся только из технической выгрузки. Покрытие ClientID рассчитывается как доля технических визитов с корректным идентификатором. Значение сохраняется строкой; если Excel уже округлил длинное число до загрузки, потерянные цифры восстановить невозможно.

## Требования к периоду

- в каждом источнике желательно не менее 5 дней данных;
- для более устойчивой оценки желательно 9–14 дней и более;
- обе выгрузки должны иметь одинаковый период и одинаковый фильтр кампаний;
- дата должна быть представлена отдельной группировкой, а не только общим периодом отчёта;
- площадки с суммарным объёмом менее 20 визитов за загруженный период исключаются до расчёта общей базы, дневных аномалий и рейтинга.

## Как считается однодневная аномалия

Для каждого сочетания `источник × дата` рассчитываются метрики и концентрации. Затем этот день сравнивается с медианой остальных дней того же источника. Проверяемый день исключается из собственной базы сравнения.

В score входят:

- всплеск дневного объёма;
- резкое повышение или подозрительно низкий уровень отказов относительно медианы остальных дней площадки;
- сильное уменьшение или неправдоподобно высокое среднее время на сайте относительно медианы остальных дней площадки;
- рост доли новых посетителей;
- отклонения конверсий;
- концентрация одного IP или подсети;
- концентрация ClientID, доля топ-1 и топ-10 ClientID, а также аномальный рост повторных визитов на ClientID;
- концентрация технического профиля;
- появление headless/automation-браузеров;
- резкий рост неизвестных браузеров.

Дни с недостаточной выборкой или короткой историей получают ограниченный score и низкую уверенность. ClientID используется только как дополнительный сигнал при достаточном покрытии и не считается самостоятельным доказательством фрода.

## Важное ограничение

Показатель `Визиты в аномальные дни` — это объём трафика, попавшего под проверку. Он не равен точному количеству доказанных фродовых визитов. Для точного подсчёта уникальных визитов потребуется выгрузка на уровне `VisitID`.
