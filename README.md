# Traffic Fraud Lab

Инструмент для анализа трафика Яндекс.Метрики на возможные признаки фрода и технических проблем измерения.

## Что изменилось в версии 1.0

Основной API-режим больше не формирует пользовательский вердикт через сумму баллов. Каждый источник проверяется отдельно по дням и по четырём независимым семействам сигналов:

1. **Идентификаторы и сети** — ClientID, концентрация IP и подсетей.
2. **Техническая однородность** — браузер с мажорной версией, разрешение, ОС и automation/headless-кластеры.
3. **Поведение** — максимум отклонения по отказам или времени; связанные показатели не складываются.
4. **Конверсионный паттерн** — неестественное достижение нескольких разных целей в одном визите.

Объём трафика не является самостоятельной уликой. Он влияет только на приоритет ручной проверки.

## Базовая линия

Для каждого дня основной базой служит медиана остальных дней того же источника. Проверяемый день исключается из своей базы. Если собственной истории недостаточно, используется медиана сопоставимых источников за ту же дату.

Сравнивается медиана с медианой. Среднее и медиана в одном правиле не смешиваются.

## Гейты данных

Правило участвует в оценке только при достаточной выборке:

- любой процент — от 30 визитов;
- поведение — от 100 визитов;
- дневные концентрации IP, подсетей и технических параметров — от 500 визитов;
- ClientID — покрытие от 50%, не менее 100 визитов с ClientID и 100 уникальных идентификаторов;
- при доле `cookies off` выше 15% ClientID помечается как ограниченно репрезентативный.

Невыполнимое правило получает статус **«нет данных»**, а не «0 нарушений».

## Дневной вердикт

Вердикт зависит от числа семейств, сработавших **в один и тот же день**:

| Семейств | Вердикт | Действие |
|---:|---|---|
| 0 | Норма | Продолжить мониторинг |
| 1 | Наблюдать | Зафиксировать и вернуться после накопления данных |
| 2 | Проверить | Запросить детализацию по дате и подразмещениям |
| 3–4 | Ограничить | Рассмотреть сокращение только после ручной проверки |

Если доступно менее двух семейств, вывод помечается как **«Недостаточно данных»**.

## Системность

Для итогового вывода по источнику используется максимальное число одновременно сработавших дневных семейств.

- более 30% аномальных дней повышают итог на одну ступень;
- менее 10% аномальных дней понижают итог на одну ступень.

Сигналы разных дат не объединяются в искусственно усиленный вердикт.

## Конверсии и качество измерения

Цели, достигнутые за 0–3 секунды, показываются отдельно как возможная ошибка разметки или автосрабатывание на загрузке страницы. Этот показатель **не повышает фрод-вердикт**.

В старых дневных агрегатах корзины времени достижения целей могут отсутствовать. В таком случае семейство получает статус `н/д`, а доступная периодная диагностика показывается отдельно и не складывается с сигналами других дат.

## Отчёт

Для каждого источника интерфейс показывает:

- итоговый вердикт и приоритет проверки;
- число аномальных и проверенных дней;
- полноту проверки: сколько семейств было доступно;
- конкретную дату, выборку и абсолютные значения для каждого сработавшего семейства;
- отдельный блок качества измерения;
- таблицу дат, которые нужно запросить у площадки;
- CSV-экспорт дневных семейств и причин.

Ни один статус не отключает источник автоматически.

## API-режим

Данные загружаются из безопасных дневных агрегатов Yandex Metrica Logs API. Поддерживаются счётчики `53197618` и `100470605`, выбор произвольного подготовленного периода и кампании с токенами `prg`, `med`, `mrk`.

Исходные IP, ClientID и VisitID используются только внутри GitHub Actions для расчёта агрегатов и не публикуются.

## Ручной режим

Ручная загрузка CSV/XLSX сохранена как резервный режим для сторонних счётчиков и локальных файлов. Она временно использует прежнюю эвристику и явно помечена в интерфейсе как fallback. Её score нельзя использовать для автоматического решения об отключении площадки.
